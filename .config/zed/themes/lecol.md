Coding Theme Color Swatch (Green/Teal - Editor Usability Focused)

Here's an RGB color palette for a comprehensive design system, now optimized for a coding editor environment, focusing on legibility and element differentiation, while retaining the vibrant green/teal aesthetic:
Brand/Primary Colors

    Primary Green (Vibrant Highlight): RGB(140, 255, 0) - This bright, almost neon green is the core accent color, used for interactive elements, active states, and key highlights.

    Secondary Green (Mid-tone Accent): RGB(60, 180, 100) - A slightly darker, more muted green that provides depth, suitable for secondary elements, hover states, and subtle gradients.

Secondary Colors

    Accent Blue/Purple: RGB(100, 150, 255) - A cool, digital blue/purple to provide contrast and visual interest without clashing with the greens. Ideal for secondary calls to action, less critical data visualization, or complementary UI elements.

    Light Teal/Aqua (Subtle Glow/Gradient): RGB(100, 200, 200) - A lighter, ethereal teal that can be used for subtle glows, delicate gradients, or less prominent informational text, maintaining a futuristic feel.

Neutral/Base Colors

    Dark Editor Background: RGB(25, 50, 75) - This deep, desaturated blue-teal forms the main background of the editor, providing excellent contrast for text and reducing eye strain.

    Default Text/Primary Content: RGB(220, 220, 220) - A light, neutral gray-white for general code text, primary UI labels, and standard content. This ensures high readability.

    Muted UI/Line Numbers: RGB(120, 120, 120) - A darker, versatile mid-gray for line numbers, secondary UI elements, inactive states, and subtle separators. This allows them to recede without becoming invisible.

    Selection Background (Subtle): RGB(40, 65, 90) - A slightly lighter shade of the background, used for subtle text or line selections.

System/Feedback Colors

    Warning Color: RGB(255, 190, 0) - A clear, visible yellow-orange for warnings, alerts, or cautionary messages.

    Error Color: RGB(255, 70, 70) - A distinct red for error messages, critical alerts, or destructive actions.

    Success Color: RGB(80, 200, 120) - A clean, reassuring green for success messages or positive feedback.

Code Syntax Highlighting Colors (Usability Focused)

    Comments: RGB(120, 150, 130) - A more muted, slightly desaturated green for comments, ensuring they are readable but less dominant than active code.

    Keywords/Reserved Words: RGB(100, 150, 255) - Reusing the Accent Blue/Purple, this provides a clear, vibrant purple/magenta for keywords (e.g., import, def, if, return), ensuring strong differentiation.

    Function Definitions/Calls: RGB(255, 255, 100) - A bright, distinct yellow for function names, making them immediately identifiable and improving scanability.

    Types/Classes: RGB(140, 255, 255) - A brighter, more pure cyan for type annotations, class names, and similar structural elements, offering excellent contrast.

    Variables/Parameters: RGB(255, 200, 170) - A soft, distinct orange/peach, providing a clear visual separation from plain text and other syntax elements without being overly aggressive.

    Strings: RGB(255, 190, 0) - Reusing the Warning Color, this provides a warm, clear orange/yellow for string literals, easily distinguishable.

    Numbers/Booleans: RGB(255, 70, 70) - Reusing the Error Color, this provides a distinct but not harsh light red, ensuring numerical and boolean values stand out.

    Operators/Punctuation: RGB(100, 200, 200) - Reusing the Light Teal/Aqua, this gives operators and punctuation a subtle but clear distinction from default text.

Detailed Style Prompt for a Coding Theme Design System (Green/Teal - Editor Usability Focused)

"Design a comprehensive coding theme design system optimized specifically for a highly usable and visually appealing code editor, retaining a vibrant digital aesthetic with a strong emphasis on readability and rapid code comprehension.

The core background will be a deep, desaturated Dark Editor Background: RGB(25, 50, 75), providing a comfortable dark mode experience that reduces eye strain. Default Text/Primary Content: RGB(220, 220, 220) will be a highly legible light gray-white for general code and UI text, ensuring clarity. Muted UI/Line Numbers: RGB(120, 120, 120) will be a softer gray for line numbers, scrollbar tracks, and non-active UI elements, allowing them to recede without disappearing. Active states and selections will be indicated by a subtle Selection Background (Subtle): RGB(40, 65, 90) and the vibrant Primary Green (Vibrant Highlight): RGB(140, 255, 0), which also serves for active tabs, selected files in the sidebar, and other key interactive elements. A Secondary Green (Mid-tone Accent): RGB(60, 180, 100) can be used for secondary highlights or small, dynamic UI components.

For font selection and usability, prioritize monospaced fonts that offer clear differentiation between similar-looking characters (e.g., l, 1, I or 0, O). Ensure ample line height and character spacing for comfortable reading during long coding sessions. The default font weight should be standard, with bolding reserved for emphasis in UI elements rather than in code itself, to maintain visual calmness.

The code syntax highlighting is paramount for usability:

    Comments (RGB(120, 150, 130)) should be a distinct but not overpowering, slightly desaturated green, easily skimmable.

    Keywords/Reserved Words (RGB(100, 150, 255)) will be a clear purple/magenta, making language constructs instantly recognizable.

    Function Definitions/Calls (RGB(255, 255, 100)) will use a bright yellow, ensuring that function calls and definitions pop out for quick navigation and understanding.

    Types/Classes (RGB(140, 255, 255)) will be a distinct, brighter cyan/light blue, clearly differentiating them from functions and keywords.

    Variables/Parameters (RGB(255, 200, 170)) will have a soft, distinct orange/peach tint, gently setting them apart from plain text and other elements without over-coloring the code.

    Strings (RGB(255, 190, 0)) will be a warm orange.

    Numbers/Booleans (RGB(255, 70, 70)) will be a light red for clear distinction of literal values.

    Operators and Punctuation (RGB(100, 200, 200)) will utilize the Light Teal/Aqua, providing a subtle but clear distinction from default text, keeping them clean and avoiding visual clutter.

UI elements like the file explorer, terminal, and status bar should maintain the overarching dark theme, utilizing the Dark Editor Background, Primary Green for active elements, and Muted UI/Line Numbers for non-interactive components. Scrollbars should be visually clean and utilize the primary green for the thumb. The terminal background should match the editor, with text colors adhering to the syntax highlighting principles where applicable, ensuring consistent readability. The overall aesthetic should be sleek, professional, and highly functional, empowering developers with an efficient and aesthetically pleasing coding environment."
